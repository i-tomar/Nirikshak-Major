# Decisions

Phase 0 starts from the existing origin/main license and the local source baseline. Phase changes remain local until gates pass.

The original synthetic fixture is unavailable. Its generator uses the UTC hour to decide which random draws to consume. We selected a fixed compatible start, 2025-01-01 16:40 UTC, with the original CLI parameters and seed 42. The unmodified generator produced 5,000 transactions, 4,915 wallets and the existing investigation fixture address. This reconstructs the tested counts and address. The original file hash is unknown. No generated row or expected count was edited.

The initial anomaly model reloads from hash-checked numeric Parquet training inputs, pinned library versions and a saved random seed. This trades reload time for safe deserialization. The alert API keeps the historical risk scoring contract. Wallet clustering is behavioral similarity. Entity inference is scheduled for Phase 3.

BABD-13 dropped (file too large for the dev machine); real-data track uses Elliptic and BitcoinHeist.

Both baseline 0d06e64 and 32ebd44 generated the same CSV, SHA-256 be9448ac22895089f0274ded4dc9b63100db0e4b17ac688faf5f7981a85ca937. With 5,000 transactions, 4,915 wallets, 5,000 observations and zero rejected rows on both, independent Decimal summation and DuckDB each gave 5216.56493532 BTC on both revisions. The baseline package initializer was bypassed in the scratch worktree because it imports the missing ML module. The actual generator, schema, loader, normalizer and storage were unchanged. The legacy fixture was unavailable. Phase 3 verification now derives expected volume and timestamp boundaries directly from source CSV and retains the original precision and table-count checks. Phase 5 inherits this correction through its regression runner.

API failure tests cover server-side correlation IDs, sensitive detail redaction, configured CORS and default-disabled documentation. Alert literal-input tests cover punctuation, Unicode and length without requiring application data mutations.

Phase 0 lint cleanup uses Ruff safe autofixes for import order, modern type syntax and formatting; remaining broad exception catches were narrowed to file, parse, graph and database errors. The normalizer wallet accumulator now has an explicit TypedDict. Empty DuckDB COUNT results are handled as zero, and Polars scalar statistics convert through strings because Polars' broad return union includes nonnumeric types. Mypy remains enabled without global relaxations.

Third-party imports without bundled type markers use narrow `ignore[import-untyped]` comments at: `app/graph/{builder,queries,serializers}.py` (NetworkX), `app/ml/{anomaly,risk}.py` (SciPy), `app/ml/{anomaly,clustering}.py` (scikit-learn), `app/ml/clustering.py` (threadpoolctl), and `scripts/verify_phase5.py` (NetworkX). Each exception is limited to its import line; no application module is exempt from analysis.

The new HTTP regression tests use one-row Parquet fixtures and a separate leakage sentinel. They send SQL operator, comment, UNION, stacked-statement, null-byte, Unicode, overlong, and traversal strings to alert and investigation query and path inputs. They check valid IDs, result limits, redacted responses and unchanged Parquet hashes. FastAPI's default 422 body echoes rejected input, so Phase 0 now returns a generic 422 detail. The investigation route's own 400/404 detail also echoed wallet input, and now uses static text. These tests were added to close the injection gate; existing tests were not weakened, skipped or removed.

Phase 1 adds the vectorized `ingest_file` path for CSV, JSON arrays/wrappers, NDJSON and defused XML. The legacy Pydantic list helper remains for Phase 0 seed and benchmark compatibility; the HTTP upload now uses vectorized ingestion. Large uploads above 50,000 valid transactions finish the data layer and explicitly return `pipeline_status=PARTIAL` because the current graph and ML stages are not bounded at that scale. This avoids presenting incomplete analysis as a success. The Phase 0 investigation security test fixture was adjusted to write only the three tables its route reads after `normalize_dataset` began returning four additional tables; no assertion or attack case was removed.

Phase 1 adds one narrow `ignore[import-untyped]` at each `defusedxml.ElementTree` import in `app/pipeline/loader.py` and `app/pipeline/streaming.py`, each PyArrow import in `app/pipeline/streaming.py`, and the `defusedxml.common` import in `tests/test_phase1_formats.py`. These installed libraries do not ship mypy type markers. No module-level ignore or global mypy flag was added.

The GeoIP resolver uses supplied country/ASN when complete, otherwise the offline MMDB database when available, and finally a committed synthetic CIDR table. Source labels are included in normalized `ip_enrichment`, upload responses, statistics responses and server logs. Unmapped private, invalid and IPv6 values remain unknown and are labelled; the fallback never invents a public country for an unmapped IP. DB-IP Lite compressed databases were present locally and exercised in the benchmark. They remain ignored and read-only.

The canonical schema is `schema_v2`, with `schema_v1` retained as an accepted input wrapper for the existing fixture. Both versions accept the five explicit Bitcoin script types P2PKH, P2SH, P2WPKH, P2WSH and P2TR. Streaming timestamps are parsed as ISO-8601 with UTC offsets or `Z`, and normalized to UTC with microsecond precision; naive ISO-8601 timestamps are interpreted as UTC by the DuckDB session setting. Invalid timestamps enter rejected.parquet. The original Phase 0 list loader remains for legacy verification, while the HTTP upload uses the versioned streaming path.

The first full Phase 1 run exposed an active-dataset replacement bug: an all-rejected upload wrote empty core Parquet files, causing legacy verifiers 4 and 5 to see zero wallets after verifier 2. The ingest path now writes staged files on the destination volume and promotes core tables only when valid rows exist; all-rejected input updates only `rejected.parquet`. A runtime test compares core Parquet bytes before and after rejection. A Windows attempt to stage in the system temp directory failed with WinError 17 across C: and D: drives, so staging now occurs under the destination directory. Static SQL and bound values replaced dynamic SQL fragments after Bandit B608 identified three possible injection sites; no Bandit suppression was added.
